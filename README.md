# 抖音推荐流过滤器

Chrome (MV3) 扩展：在抖音网页版首页推荐流里，按**发布时间**和**关键字**自动屏蔽视频，也可以**右键一键屏蔽某个博主**。

只作用于 `https://www.douyin.com/?recommend=1` 的推荐流接口，不改搜索页、用户主页、评论区。

## 安装

1. 打开 `chrome://extensions`，右上角开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选择本仓库根目录（含 `manifest.json` 的文件夹）。
3. 打开抖音网页版首页推荐流，点工具栏图标设置阈值和关键字，保存后**刷新页面**。

## 设置项

| 项 | 说明 |
| --- | --- |
| 总开关 | 关闭后完全不改页面行为 |
| 隐藏发布超过 N 小时 | 单位是小时，默认 720（约 30 天）。老版本存的「天」会自动 ×24 迁移 |
| 屏蔽关键字 | 每行一个，命中视频标题、作者昵称或直播房间标题即屏蔽（不区分大小写、子串匹配），屏蔽制、不做白名单 |
| 已拉黑博主 | 右键「拉黑该作者」写进来的独立列表，按账号 ID 认人，弹窗里可逐个移除 |

设置存在 `chrome.storage.sync`，可随账号同步。

## 拉黑博主（右键）

在播放器区域右键 →「拉黑该作者」（这一行是扩展补进**抖音自己的右键菜单**里的，样式跟它原有菜单项一致）。点一下把**当前正在播放这条内容的作者**写进拉黑名单，并立刻跳过它；之后这个博主的视频和直播都不再出现。

- 拉黑和屏蔽关键字是**两份独立列表**：拉黑名单存在 `chrome.storage.sync.blocked`，弹窗里单独一节可以逐个移除。
- 拉黑按 `sec_uid`（账号 ID）认人，对方改名也照样拦得住；接口没给 sec_uid 的卡片退回昵称**精确**匹配（不是子串，不会误伤同名前缀）。
- 认作者有三条路，按可靠性依次退回：① `data-e2e-vid` 属性对接口元数据；② **播放地址对接口元数据**——把正在播的 `video.currentSrc` 去掉签名 query、只留路径末两段，和接口里的 `play_addr.url_list[0]` 比，不依赖任何属性名；③ 页面 DOM——从播放中的 `video` 逐级往上找作者链接 `a[href*="/user/<sec_uid>"]`，空文字的图标链接会跳过继续找。三条都失败只会提示"没认出手上这条的作者"并打出各环节计数，不会写坏配置、也不会认错人。
- 登录态判断刻意做成"只认正向证据"：**顶栏**（页面上部 140px 内）有可见的「登录」按钮才当作未登录、不给这一行；判不准就照常给入口。（早先用 `document.cookie` 里的 `sessionid` 判断，结果登录态也读不到那个名字，把整行菜单藏了——别再拿 cookie 名当依据。）浏览器原生右键菜单里还留了同名备用入口，只在 `douyin.com` 页面出现。

## 工作原理

- `hook.js`（MAIN world / document_start）覆盖 `XMLHttpRequest.prototype` 的 `responseText` 和 `response` 两个 getter，对推荐流接口的响应**先统计再落刀**：把命中规则的条目从作品数组里删掉后交还给页面。卡片从未进入页面的待播队列，所以表现为「视频凭空消失」，没有滚动动画。`fetch` 也做了同样处理，防止站点改传输方式后失效。
- 命中规则依赖 `create_time`（秒级时间戳）。卡片 DOM 上不显示发布日期，接口响应是唯一可靠来源。
- `content.js`（isolated world）保留**滚动跳过兜底**：合成 `keydown`/`keyup` ArrowDown 跳下一条，用于「整页全部命中」和接口层漏网的情况。整页命中时不改写响应——实测把每页删空会让播放器卡死不再续拉，这条保护不能去掉。
- 配置下发走跨世界共享的 `localStorage['dyfilter-cfg']` + `document.documentElement.dataset.dyConfig`。反向 `postMessage` 在部分内核上不可靠，不再用作配置通道。
- 识别屏蔽条目按**对象形状**而非固定字段名，兼容 `aweme_list` / `item_list` / `data` 等层级，以及 `{aweme:{}}`、`{aweme_info:{}}` 包装卡片，避免站点换字段名后过滤静默失效。
- **直播卡片**同样处理：主播名可能挂在 `owner` / `user`，房间标题在 `title` / `live_title` / `status` 而非 `desc`，按形状取值后关键字屏蔽照常生效。直播没有"发布时间"（`create_time` 是开播时间），因此**不参与时间阈值判定**，只受关键字屏蔽。
- `background.js`（MV3 service worker）只负责注册浏览器原生右键菜单并把点击事件转给当前标签页的 `content.js`；写拉黑名单仍走 `chrome.storage.sync`，`hook.js` 通过现成的配置通道实时读到。抖音自绘菜单里那一行由 `content.js` 注入（isolated world 与页面共享 DOM，能直接改）。
- 判定"手上这条"时，同时处于播放态的 `video` 可能不止一个（预加载的下一条未必 `paused`），取**视口里占面积最大**的那个，避免拉黑到还没看到的那条的作者。

## 弹窗「运行状态」怎么读

数字每秒自刷新，不用关弹窗重开；每次刷新抖音页后重新计数。

- `过滤脚本` / `页面注入`：content script 与 MAIN world 注入是否活着。
- `无痕屏蔽 N 个`：在接口响应里被直接删掉的条数（无感）。
- `滚动跳过 N 个`：走兜底按键跳掉的条数。
- `页面生效阈值`：页面真正在用小时间隔。和设置值不一致时说明配置没下发，点保存再刷新页面。
- 若「无痕屏蔽」一直是 0，会显示 `补丁模式` 并提示接口层改写未生效，此时只剩滚动兜底。
- 若显示「未检测到抖音登录态」，右键菜单里就不会有「拉黑该作者」这一行——不是注入坏了，是没登录。
- 拉黑没认出作者时，弹窗会显示一行 `上次拉黑没认出作者：视频N 在播N vid键有/无 元数据N 地址索引N src… 作者链接N`（5 分钟内有效）。把这行原样发我，就能看出是哪一条链断了：`在播0` 是播放器状态没认出来，`元数据0` 是接口采集没跑通，`作者链接0` 是页面上没有 `/user/` 链接。

## 开发与自测

页面注入逻辑有 Node 桩环境回归测试，改动 `hook.js` 后必须跑：

```bash
node test-hook.mjs    # 覆盖过滤改写、整页命中不改空、包装卡片、直播卡片字段路径、关键字、开关
node test-content.mjs # 覆盖兜底判定、作者识别（接口元数据 / 播放地址 / 页面链接）、多条在播取视口最大者、拉黑写入与去重、登录态、菜单注入识别
node test-popup.mjs   # 覆盖弹窗统计渲染与保存链路
```

真实扩展加载和弹窗观感只能手动验证：浏览器内嵌自动化环境无法加载解压扩展，`chrome.*` 相关行为（world 支持、storage 权限差异）也测不到。

## 已知限制

- 只在抖音**网页版首页推荐流**生效，且需要页面继续用当前这套 feed 接口；接口路径或字段大改时需要更新 `hook.js` 里的 `FEED_URL_RE` 与识别规则。
- 重载扩展后，页面里旧版 content script 会变成孤儿并反复报 `Extension context invalidated`；扩展代码会自行判活停止上报，但**每次重载扩展请顺手 F5 刷新抖音页**。
- 部分浏览器内核对 `chrome.storage.sync.onChanged` 等 API 支持不全，代码一律先特性检测再调用。
- 注入抖音自绘右键菜单靠的是「弹出浮层 + 贴着鼠标位置 + 至少两行」的形状识别；如果那个菜单被放进 shadow DOM / iframe，或弹在离鼠标很远的位置，就只会有浏览器原生菜单那一个入口。
