# 抖音推荐流过滤器

Chrome (MV3) 扩展：在抖音网页版首页推荐流里，按**发布时间**和**关键字**自动屏蔽视频。

只作用于 `https://www.douyin.com/?recommend=1` 的推荐流接口，不改搜索页、用户主页、评论区。

## 安装

1. 打开 `chrome://extensions`，右上角开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选择本仓库根目录（含 `manifest.json` 的文件夹）。
3. 打开抖音网页版首页推荐流，点工具栏图标设置阈值和关键字，保存后**刷新页面**。

## 设置项

| 项 | 说明 |
| --- | --- |
| 总开关 | 关闭后完全不改页面行为 |
| 隐藏发布超过 N 小时 | 单位是小时，默认 720（约 30 天）。老版本存的「天」会自动 ×24 迁移 |
| 屏蔽关键字 | 每行一个，命中视频标题**或**作者昵称即屏蔽（不区分大小写），屏蔽制、不做白名单 |

设置存在 `chrome.storage.sync`，可随账号同步。

## 工作原理

- `hook.js`（MAIN world / document_start）覆盖 `XMLHttpRequest.prototype` 的 `responseText` 和 `response` 两个 getter，对推荐流接口的响应**先统计再落刀**：把命中规则的条目从作品数组里删掉后交还给页面。卡片从未进入页面的待播队列，所以表现为「视频凭空消失」，没有滚动动画。`fetch` 也做了同样处理，防止站点改传输方式后失效。
- 命中规则依赖 `create_time`（秒级时间戳）。卡片 DOM 上不显示发布日期，接口响应是唯一可靠来源。
- `content.js`（isolated world）保留**滚动跳过兜底**：合成 `keydown`/`keyup` ArrowDown 跳下一条，用于「整页全部命中」和接口层漏网的情况。整页命中时不改写响应——实测把每页删空会让播放器卡死不再续拉，这条保护不能去掉。
- 配置下发走跨世界共享的 `localStorage['dyfilter-cfg']` + `document.documentElement.dataset.dyConfig`。反向 `postMessage` 在部分内核上不可靠，不再用作配置通道。
- 识别屏蔽条目按**对象形状**而非固定字段名，兼容 `aweme_list` / `item_list` / `data` 等层级，以及 `{aweme:{}}`、`{aweme_info:{}}` 包装卡片，避免站点换字段名后过滤静默失效。

## 弹窗「运行状态」怎么读

数字每秒自刷新，不用关弹窗重开；每次刷新抖音页后重新计数。

- `过滤脚本` / `页面注入`：content script 与 MAIN world 注入是否活着。
- `无痕屏蔽 N 个`：在接口响应里被直接删掉的条数（无感）。
- `滚动跳过 N 个`：走兜底按键跳掉的条数。
- `页面生效阈值`：页面真正在用小时间隔。和设置值不一致时说明配置没下发，点保存再刷新页面。
- 若「无痕屏蔽」一直是 0，会显示 `补丁模式` 并提示接口层改写未生效，此时只剩滚动兜底。

## 开发与自测

页面注入逻辑有 Node 桩环境回归测试，改动 `hook.js` 后必须跑：

```bash
node test-hook.mjs    # 覆盖过滤改写、整页命中不改空、包装卡片、关键字、开关
node test-popup.mjs   # 覆盖弹窗统计渲染与保存链路
```

真实扩展加载和弹窗观感只能手动验证：浏览器内嵌自动化环境无法加载解压扩展，`chrome.*` 相关行为（world 支持、storage 权限差异）也测不到。

## 已知限制

- 只在抖音**网页版首页推荐流**生效，且需要页面继续用当前这套 feed 接口；接口路径或字段大改时需要更新 `hook.js` 里的 `FEED_URL_RE` 与识别规则。
- 重载扩展后，页面里旧版 content script 会变成孤儿并反复报 `Extension context invalidated`；扩展代码会自行判活停止上报，但**每次重载扩展请顺手 F5 刷新抖音页**。
- 部分浏览器内核对 `chrome.storage.sync.onChanged` 等 API 支持不全，代码一律先特性检测再调用。
